★概览 & 技术栈

“作业小龙”是一个让孩子通过完成作业养成小龙的激励系统：做完作业得经验/龙币，龙币可消费、兑换零花钱，家长端配置任务与评价。核心循环是 作业 → 奖励 → 宠物成长 → 更多动力。

后端

Python FastAPI（单文件 main.py 2141 行），原生 sqlite3，uvicorn 运行

数据层

SQLite + WAL 模式，database.py 建表与向前兼容 ALTER

前端

index.html 单页（Jinja2 + 原生 JS），?role=kid|parent 双视图

渲染

②后端架构 (main.py)

单文件分层：配置/工具函数 → 页面路由 → 按业务域分组的 API → 定时任务 → v3.2 皮肤/算术题。所有 DB 操作为同步 sqlite3，每个请求内 get_db_connection() 开闭。

配置常量

DEFAULT_TASKS(5科)、CUSTOM_TASK_TEMPLATES(12)、FOCUS_COINS、TREASURE_REWARDS、EVOLUTION_THRESHOLDS=[0,800,2000,4000,8000]、PET_SKINS(5款)

进化系统

calculate_evolution_stage / stage_progress / get_pet_appearance / get_stage_svg_info（5 阶段：龙蛋→幼龙→少年龙→青年龙→神龙）

工具函数

get_today_tasks_summary、add_coins(原子交易+周末双倍)、check_achievements(17成就)、calculate_realtime_decay(实时衰减)

页面路由

API 路由

约 45 个，按 作业/互动/行为/龙币/专注/商店/设置/活动 分组（见④）

定时任务

POST /api/scheduler/run：睡眠结束唤醒、21点无作业→睡觉、实时衰减、过期任务清理

关键设计：所有奖励写入 coin_transactions 保证可审计；add_coins() 是龙币唯一入口（原子更新余额+交易记录）。成就检查散落各写完逻辑中调用 check_achievements()。

⑥核心数据流：完成作业

一次“完成作业”如何串联起经验、龙币、进化、成就与状态。其余动作（喂食/互动/专注/商店）模式类似。

① 前端提交POST /api/task/complete (subject)
→
② 防重 & 奖励查今日是否已做；取 SUBJECT_REWARDS(数学双倍)
→
③ 写 tasks插入完成记录；累加 exp/hunger/mood
→
④ 连续天数streak / math_streak 按昨天判定
⑤ 龙币add_coins(周末双倍+挑战赛+20)
→
⑥ 进化判定calculate_evolution_stage 对比新旧阶段
→
⑦ 宝箱数学60%/普通10% 触发称号/道具/经验卡
→
⑧ 成就check_achievements 解锁
→
⑨ 返回前端播放动画/粒子
闭环原则：所有数值变更都经过单一函数（如 add_coins），并写入流水表，便于审计与回放。

⑦双角色模型

同一页面，?role= 决定可见模块。家长模式额外需密码验证。

⑨注意 & 技术债

来自开发与运维中已确认的关键点（详见项目 MEMORY.md）。

⚠️ Jinja2 3.1.x 兼容：必须用 jinja2.Environment 直接渲染，Jinja2Templates 会报 unhashable type: 'dict'。
⚠️ SQLite 不能调用 Python 函数：SQL 中不可写 level = calculate_level(?)，须在 Python 端算好再传参。
⚠️ database is locked：已用 WAL + busy_timeout=5000 解决；并发读写仍建议单 writer。
⚠️ 科目三处必须一致：DEFAULT_TASKS / get_today_tasks_summary / SUBJECT_REWARDS（语文/数学/英语/课外阅读/体育锻炼）。
✅ 历史脚本 main_new.py / implement_features.py / fix_main.py 不参与运行，可归档或删除以免混淆。
